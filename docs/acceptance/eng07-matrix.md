## Decision and scope

**This is a coverage and evidence-gap baseline, not an acceptance certificate. No ENG-07 live requirement is closed by this document.** Source and test references below are pinned to the requested commit, not to a moving PR head. Test presence, a source assertion, a deterministic native port, and a successful real native Run are different kinds of evidence.

The only current model is one `WorkflowVersionV3`, one engine and one Start family. Ordinary workflows omit `repeat` entirely; they have real execution/technical-attempt history and no manufactured occurrence, carry or decision rows. A configured finite repeat is optional V3 behavior, not another engine or a V1/V2 compatibility mode. The single mounted Board is the workspace before, during and after a Run.

**Meaningful changes must not publish while any affected Run is active or has unsettled obligations.** Stage the exact change; obtain authorized Stop for affected Runs when needed; wait for durable terminal, native, credential, interaction, review and cleanup settlement; then publish with the original command identity and workflow revision revalidated. Stop acceptance alone is insufficient. Already-settled Runs do not need a gratuitous Stop. Geometry-only changes are a separate, non-executable path. Old evidence showing meaningful Save while a Run continues is **obsolete**, even when immutable old Run pins were preserved.

Related deliverables: [active-reference retirement inventory](eng07-retirement-inventory.md) and [supported-limits register](../architecture/execution-runtime-v3.md).

A filename alone is not a claim that every case in that file qualifies this requirement.

Every live evidence bundle must identify the exact candidate SHA; OS, PostgreSQL, CLI and model versions; configuration and execution-location pins; authenticated caller/source; workflow/version/revision; command IDs and payload hashes; Run, node, slot, execution and technical-attempt IDs; native session/thread/process lifetime and terminal/ACK identities; accepted input/result digests and protected exact-value artifacts; closure/credential/cleanup receipts; and repeat occurrence/decision/carry IDs only where real. Screenshots, spinners, elapsed time, a missing registry directory, a delivered approval, a Stop receipt, an HTTP 200, or a synthetic provider response cannot stand in for the missing durable/native proof.
