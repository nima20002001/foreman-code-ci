# Concrete CLA-B domain adapter mounting

`createPostgresClaudeInteractionBridge({database,binding,manager,configuration})` creates ONE existing SDK callback map and a concrete Postgres authority (no parallel pending/response store).

- `binding.workflow`: actual `runId`, `executionId`, integer `attempt`, and private `getOwner(): RunOwnership | undefined` getter. Input admission uses the actual owner/fence; response validation uses current existing `credentialAuthority(...,'workflow')`; it preserves V3 immutable versions/configuration, native lane, budget and cleanup checks. Sender comes from the Run's persisted `authorizationPrincipalId`. SDK `attemptId` is the exact persisted execution attempt converted to string, NOT a new UUID or request identity.
- `binding.operator`: actual conversation, existing `PostgresOperatorConversationRepository.pending`.
- `binding.agent`: actual conversation, workspace ID, existing `PostgresAgentChatRepository.pending`. Sender comes from the admitted turn payload ownerPrincipalId; no Operator MCP credential issuer is called.
- `manager` is the actual A manager's `nativeCallbackContext(nativeSessionId,toolUseId)`. It must return the observed input native message, client correlation and SDK callback generation. Pass a lazy forwarding wrapper while constructing the manager, not caller JSON.

Call returned `callbackAdmission()` asynchronously for each admitted SDK input; chat model attempt/sender comes from the current persisted active turn, never the first-turn constructor. Before building actual SDK callbacks; use its owner/attempt values unchanged. Returned `bridge` mounts A's createClaudeSdkCallbacks. Returned `interactionPort` mounts A's actual pending/respond/reconcileResponse hooks; `.bridge.subscribePending(...)` supplies the exact `{nativeSessionId,nativeMessageId,clientCorrelationId,generation,nativeRequestId,nativeRequestType}` notification after actual insertion. A must include `.bridge.pendingInteractions(session)` in COMPLETE native history and wake the EXISTING owned workflow observer. Workflow publication remains `capture(history) -> runs.updateExecution(waiting) -> workflowNativeProof.assertNativeUpdateLocked/createRequestLocked`; B never invokes Wave25Repository.create.

Chat request publication uses the existing repository.pending guarded by admitted active model request. Actual response dispatch MUST flow through current Operator/Agent services and existing control receipts. B rechecks current sender and responder authority, exact session/input/generation/tool/control IDs and selected choice. Operator requires existing response_delivery=submitted. Agent/Operator require one existing pending management control receipt with acceptedControl retaining modelRequestId, native session/message/control request/type/SDK generation and choice. Root/W05 must add actual messageId/generation to accepted-control native shape (never a message/turn alias). Missing old metadata fails closed. Selected semantic, native harness/version and conversation/workspace scope are checked against the existing receipt.

Workflow response requires the existing ORIGINAL-SOURCE interaction, selected choice and active delivery attempt/fence/lease; no response row is manufactured. Native callback return is only local submission. A canceled callback or a decision that differs from the selected response stays uncertain. `PostToolUse` for an approved tool, or `PermissionDenied` for a denied tool, can establish native consumption only when the observed session, input message, callback generation, tool-use ID and selected response match. `reconcileResponse` returns that retained evidence through the shared response-delivery contract; missing evidence never authorizes another reply. Chat receipts store an acknowledgment before final control settlement. Resident observation can recover a lost write, and persisted matching acknowledgments permit storage-only recovery after restart or on a retry with the original command ID.

MCP tools use a separate owner-bound manifest. The `graphql` HTTP manifest comes from authenticated `tools/list` on the accepted endpoint with the same scoped credential delivered to the native query. Callback provenance must report that server and the `dynamic` source. The in-process `graphql-files` server supplies its own exact tool manifest and requires `sdk` provenance. File-only owners do not receive the HTTP manifest. Built-in qualification excludes MCP names; a matching name or native MCP status alone does not grant access.

Completed permission callbacks release their input, promise and signal references, retaining compact decision records with a 256-record owner limit. At the limit new callbacks fail closed; retained identities cannot be replayed. File calls revoke their private credential as soon as the shared service completes, while owner shutdown also closes any in-flight bridges.

Current response APIs carry optionId only. Structured multi-select/free-text AskUserQuestion remains explicitly denied until the existing response contract can store exact answers. The concrete port supports permissions; A capability discovery must not advertise question support from an injected port alone.
