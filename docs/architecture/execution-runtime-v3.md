[Acceptance matrix](../acceptance/eng07-matrix.md) · [retirement inventory](../acceptance/eng07-retirement-inventory.md)

## Interpretation

This register separates a schema/implementation bound from a user-supported operational envelope. A schema-valid value is not a promise that the whole graph, its accepted inputs/results, its native work and its public projection will fit all other bounds. Likewise, a page size, mock fixture size, cursor catch-up window or snapshot bound is **not** a retained-Run count or a database retention policy.

**No new production-scale envelope is certified here.** Numerical hard bounds below were read from the pinned source; listed tests are existing qualification targets, not executions performed for this document. Values must be rechecked when their source changes. Runtime defaults may be overridden by composition; capture actual deployed settings in live evidence rather than silently treating constructor defaults as global limits.

## Operational envelope still to approve

Before asserting a supported production size, record an explicit combination of node/edge count, flat repeat blocks and cap, total execution/retry budget, provider concurrency, input/result sizes and retained-history size. Qualify early/limit exit, Stop, restart, exact inspection and current/snapshot/delta readback **at that same combination**. Passing each limit independently is not enough: payload overhead or projection cardinality can fail first.

The acceptance owner must settle the persisted-history retention policy and the relationship between schema-valid repeat counts and bounded projections. No numeric user-facing default for repeat cap, native concurrency guarantee, multi-platform recovery claim or maximum retained-Run count is invented by this document. Where a UI supplies a value, capture the actual UI behavior separately from the required schema field.

The acceptance report must identify whether a bound is rejected before admission, during a transaction, on projection/read, or by a native provider. A safe error is not proof of successful completion at the bound. Never bypass authorization, owner/generation/session/receipt fences or byte checks to manufacture a passing upper-limit run.
