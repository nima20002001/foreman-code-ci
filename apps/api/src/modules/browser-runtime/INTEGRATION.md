## Canonical contracts and private transport ports

Shared models import the documented `*Schema` values from `@foreman-code/contracts/browser-profiles`, `browser-sessions`, and `agent-identity`, and derive TypeScript aliases with `z.infer`. `BrowserLifecyclePort` comes from the D-owned collaboration ports. B does not supply replacement shared schemas.

The separately built C0 envelopes are represented by typed private codec ports: `BrowserCanonicalCodecs`, `BrowserDeviceCodecs`, `BrowserHostMediaCodec`, and the viewer/client codec ports. D binds the exact canonical parsers, encoders, and descriptors at composition. Device `decode*` functions must authenticate the current installed credential and resolve the existing principal; a caller-supplied JSON principal is never authority. The typed test fakes use opaque references instead of inventing shared request schemas. Full C0 linkage has not been compiled in this source delivery.

On Main, `createBrowserDeviceTransport(pairing, wire, codecs)` implements both `BrowserProfileTransport` and `BrowserSessionTransport`. Bind `BrowserDeviceWire.request/upload/download` to the existing paired transport. Metadata commands are limited to 16 KiB and ordinary encoded results to the existing 1 MiB message bound. File chunks and encrypted snapshot streams use authenticated byte routes with chunks no larger than 256 KiB. A single file read/write is bounded to 256 KiB. A legal screenshot may contain up to 2 MiB and uses those byte routes in multiple chunks, not the ordinary metadata RPC. Authority is checked before upload consumption, after operations, and during streaming. Binding replacement rejects the operation without returning partial success.

The host implementation is `createBrowserHostDeviceEndpoint`, exported by the verified native module. Main supplies `createBrowserDeviceKeyEndpoint` using `createBrowserProfiles().keyService`; host key requests use `createBrowserHostKeyRequests`. Key envelopes remain bound to the current source/recipient installation and admitted immutable snapshot. These private messages carry no new grants.

The media codecs bind the dedicated socket protocol with bounded messages, heartbeat, ordered ingress, and backpressure. Each viewer has at most one replaceable latest frame. Commands and control metadata do not queue behind frame bytes. A detached bounded view read does not retire the durable view; explicit close, disconnect, session closure, or abandoned-allocation cleanup retires capture. Stable view admission IDs prevent duplicate capture when an acknowledgement is lost. Unconfirmed capture stop remains reachable for a close retry.

## Storage, shutdown, and runtime updates

Profile creation, deletion, export, receive, apply, and pruning retain exact intent revisions and immutable snapshot identity. Sync proceeds from the chosen source and records offline/busy recipients without repeated semantic catalog/job revisions. An undispatched offline export releases its source reservation; an uncertain dispatched export keeps the reservation and reconciles the original operation. Snapshot publication uses canonical cookie/local-storage state, encrypted transfer bytes, and Main-owned per-publication keys. Retention preserves the current/prior publication plus every active or uncertain operation reference.

Host admission stops before runtime drain. In-flight profile maintenance and allocated-but-not-yet-persisted sessions count toward drain; final mutation admission is checked inside B’s maintenance gate. Host shutdown enumerates both persisted profiles and the native driver’s live/opening/reconnecting ownership. It does not infer native ownership only from completed session records. Close and private runtime-control shutdown are coalesced and retryable.

Runtime activation checkpoints profile state only after native work is drained. Successful Main and Worker cutovers invoke `pruneBrowserRuntimeVersions`, which also invokes B’s `pruneBrowserRuntimeProfiles`. That pruning preserves active generations, the compatible rollback checkpoint, preparing/uncertain checkpoints, and newer staging work; old generations are removed only after stopped-process proof. It does not run on computer-card reads or add a background directory scan.

Profile removal calls file cleanup only for sessions whose exact `setupForProfileId` matches the deleted profile. It waits for in-flight file reads, removes those setup downloads and transient native staging, and preserves execution/conversation outputs. Ordinary session close preserves completed downloads, cancels uploads/partial downloads, and writes a durable closed-session fence so late native events cannot recreate staging. Cleanup can retry even when the metadata was already marked canceled.

`runtime/browser/manifest.json`, `runtime-lock.json`, and `LICENSES.txt` are source inputs to the reproducible assembly path. Run `scripts/browser-runtime-install.mjs assemble` through Foreman CI/fleet on the requested native target. Assembly checks its OS release, architecture, libc and Node runtime, verifies the pinned executable downloads, runs native readiness, and emits a checksummed artifact plus `index.json`. Tests consume provisioned user-namespace support or an explicit `CHROME_DEVEL_SANDBOX` and `CHROME_DEVEL_SANDBOX_SHA256`; they do not provision privileged binaries.

Pass the collected runner artifact directory to release assembly through `FOREMAN_CODE_BROWSER_RUNTIME_ARTIFACTS`. Its index has `format: 1`, `sourceCommit`, and `artifacts` entries containing `directory`, `target`, and `descriptorSha256`. Each directory is relative to the index. Main consumes matching artifacts, checks their source and every transferred chunk, and never cross-builds browser units. Browser units support Node 22 patch changes; OS release, architecture and libc must still match. Core Worker targets retain their separate exact Node contract.

Missing or failed browser setup is explicit in the Worker artifact, installed `browser-runtime/status.json`, and Main release's `browser-runtime.json`. Core installation can complete so repair remains reachable. Worker `retry()` uses the selected release under its running owner; Main can repeat `stageProductionBrowserRuntime` for the same release, then use the normal activation lifecycle. Release assembly retries previously failed artifact resolution. D must connect these repair/status surfaces to existing Settings and Operator maintenance composition and supply the collected fleet artifacts. Starting a node, reading a computer, or displaying settings does not install dependencies.

Bind sync readback to `BrowserProfileSyncPageSchema`. The page retains aggregate job state and includes the profile metadata for every returned target. `BrowserProfileSyncJobSchema` continues to validate complete jobs. Explicitly removed replicas carry the `removed` exclusion until Add here reverses their saved removal intent.
